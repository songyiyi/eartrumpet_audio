固件烧录指南

从拉依赖到看见数据的完整流程。烧录本身只是把一个文件拖进 U 盘，真正需要交代的是怎么确认它跑起来了——板上两盏灯就是主要的反馈通道。

03

烧录方式一 · 拖拽（推荐）

Nucleo 板载的 ST-Link 会把自己模拟成一个 U 盘，把 .bin 拖进去就完成烧录。不需要任何软件。

  1. 用 USB 线连接 Nucleo 的 CN1 口（靠近 ST-Link 那一侧，不是 USB User 口）
  2. 等待电脑出现一个名为 NOD_H743ZI 的可移动磁盘
  3. 把 build/capture.bin 复制进去
  4. 板上 LD4（COM 灯）会红绿交替闪烁几秒，表示正在写入
  5. 磁盘会自动弹出并重新挂载，烧录完成，程序立即开始运行

也可以用 Makefile 一步完成（把盘符改成你系统上的实际值）：

mingw32-make flash NUCLEO_DRIVE=/d
Windows 上的一个已知怪象

复制完成后 Windows 有时会弹出"复制失败"或"设备已被移除"的提示，但烧录其实成功了。原因是 ST-Link 写完 Flash 后会主动重新挂载磁盘，Windows 把这个当成了拔出。

判断依据不是弹窗，而是板上的灯（见第 05 节）。真正失败时磁盘里会出现一个 FAIL.TXT，打开能看到原因。

别拖错文件

这种方式只认 .bin。拖 .elf 或 .hex 进去不会报错，但也不会正确烧录。

04

烧录方式二与三

OpenOCD（开源，无需 ST 账号）

如果拖拽方式不可用，或者你想要带校验的烧录：

openocd -f interface/stlink.cfg -f target/stm32h7x.cfg \
  -c "program build/capture.bin 0x08000000 verify reset exit"

verify 会回读比对，比拖拽方式多一层保障。OpenOCD 可用包管理器安装，与 ST 无关。

STM32CubeProgrammer

ST 官方图形工具，功能最全（能读 Flash、看选项字节、做量产烧录）。但下载需要注册 ST 账号，这也是我们整个工程刻意不依赖它的原因。前两种方式够用就不必装。

05

怎么确认它跑起来了

板上两盏灯就是主要的反馈通道。固件刻意把状态用灯表达，这样不接电脑、不用任何工具也能判断。

LED 状态对照
绿灯 LD1红灯 LD3含义下一步
每秒闪一次 灭 一切正常，采集在跑 接电脑收数据
每秒闪一次 亮 采集正常，但串口丢过块 降低 BOARD_VCP_BAUD 或改送 16 位
不闪 常亮 初始化失败，卡在 Error_Handler 八成是时钟配置，见下方
不闪 灭 程序没跑起来 烧录是否成功？按一下黑色 RESET 键
红灯常亮最常见的原因

HSE 起振失败。Nucleo 上的 8 MHz 不是晶振，而是 ST-Link 通过 MCO 送过来的方波，所以固件里配的是 RCC_HSE_BYPASS 而非 RCC_HSE_ON。

如果你换到别的板子（比如 WeAct 核心板，那上面是真晶振），必须把 src/clock.c 里改成 RCC_HSE_ON，否则一定卡在这里。

06

接收数据

Nucleo 除了模拟 U 盘，还会虚拟出一个串口。先找到它：

python tools/capture.py --list

输出里带 STLink 或 ST-Link 字样的那个就是。

敲击测试（确定左右声道）

python tools/capture.py COM5 --monitor

屏幕上会滚动显示两个通道的 RMS、峰值和直流分量。用手指轻敲骨导传感器，看哪个通道的 RMS 跳——那个就是骨导。

方案约定左（CH0）＝骨导。如果实测相反，改固件里两个 SELECT 的接法，或者直接在处理时交换声道——改软件比改硬件容易。

正式录制

python tools/capture.py COM5 out/rec.wav -d 20

录 20 秒存成 24 位立体声 WAV，然后进调参界面：

python tools/tune_gui.py out/rec.wav
07

故障排查

症状先查
电脑不出现 NOD_H743ZI 磁盘USB 线是否只有供电没有数据（很常见）；换根线试。或换插 CN1 口
磁盘里出现 FAIL.TXT打开看内容。多为文件格式不对（拖了 .elf）或 Flash 保护
capture.py 收不到任何数据① 绿灯是否在闪　② 波特率是否与固件一致　③ 串口号是否选对
收到数据但全是零传感器还没接。固件本身没问题，DFSDM 会一直输出
数据的 DC 接近 ±1数据线卡死或悬空。查 PC7 接线与传感器供电
丢块计数持续增长串口带宽不够。48k×2ch×24bit = 2.88 Mbit/s，需要 4 Mbaud 才有余量
编译报找不到头文件firmware/vendor/fetch.sh 是否执行过
串口带宽这一条值得提前知道

固件设的是 4 Mbaud。STLINK-V3E（Nucleo-H743ZI2 板载）支持，但更老的 ST-LINK/V2-1 可能跑不到。若红灯亮且丢块持续增长，两条退路：把 inc/board.h 的 BOARD_VCP_BAUD 降到 2000000，同时把发送改成 16 位（带宽减半）；或者降低采样率。

阶段 0 只是采素材，16 位完全够用——传感器本身也只有 64.5 dB 信噪比。

08

一个必须说清楚的前提

这份固件从未在真机上运行过

它已通过 Cortex-M7 交叉编译，并用 nm 验证了 DMA 缓冲落在 D2 SRAM（0x30000000）——这能排除一大类错误。但时钟树、DFSDM 通道配对、串口带宽这三处只有上电才知道。

所以实验手册第 1 步是先只测开发板、量 CKOUT 频率，不要一上来就接传感器。那一步不过，接什么都白搭。

对应固件 firmware/nucleo-h743，接收脚本 tools/capture.py。硬件与实验流程见设计方案与阶段 0 实验手册。
