01

我们在做什么

读完知道这个设备为什么能成立、为什么还不确定能成立，以及本教程到底要验证什么。

你说话时听到的自己，和录音里的自己不一样。原因是你听到的是两路声音的叠加：气导（嘴 → 空气 → 耳朵，别人听到的那路）加上骨导（声带与颅骨振动直接传到耳蜗）。骨导多出来的中低频能量，就是"自己听自己更厚、录音更薄"的来源。

所以这个设备做两件事：同时采集这两路信号，然后按比例混合再输出给调音台。骨导用贴在皮肤上的振动传感器（V2S200D），气导用嘴边的麦克风（IM69D130）。

两块传感器板并联在同一组 4 根线上。两颗传感器靠各自的 SELECT 引脚一高一低，分占时钟的两个边沿——所以两路信号在硬件层面天然同步，不存在先后。

为什么现在还不确定它能成立

贴在皮肤上测到的振动，不等于耳蜗实际感受到的骨导声——中间隔着一个因人而异、无法直接测量的颅骨传递函数。能逼近到什么程度，只有实验能回答。本教程的全部目的就是做这个实验；软件、固件、调参界面都已经写好并验证过了，就差真实的传感器信号。

本教程结束时你要拿到的三个答案
问题怎么算回答了
这条路能不能出好声音存在某组参数，让处理后的声音与你自然的自听"融"在一起
骨导探头贴哪里最好乳突／下颌骨／喉部三处，哪个信号最干净、中频最完整
参数落在哪调参界面三个滑块的最终位置
02

准备电脑

在买任何硬件之前，把软件跑起来、用合成信号把调参界面玩熟。这样硬件到货时你只需要面对硬件问题。

2.1 取代码

git clone https://github.com/songyiyi/eartrumpet_audio.git
cd eartrumpet_audio

2.2 Python 环境

需要 Python 3.10 以上。建虚拟环境，装依赖：

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

下文所有 python 命令都指 .venv\Scripts\python.exe。嫌长可以先激活：.venv\Scripts\activate。

检查点

跑自检，应显示 全部 11 项通过：

python tests/test_chain.py

2.3 C 编译器（MinGW-w64）

调参界面要把固件的 C 代码编译成动态库来实时处理音频。推荐 WinLibs 的免安装包：

  1. 到 winlibs.com 下载 UCRT · POSIX · x86_64 的 zip
  2. 解压到 C:\Users\你的用户名\.local\mingw64
  3. 把 …\mingw64\bin 加进用户环境变量 PATH
检查点

新开一个终端：

gcc --version
mingw32-make --version

两条都能打印版本号即可。

2.4 ARM 交叉编译器

编译 STM32 固件用。到 xpack-dev-tools/arm-none-eabi-gcc-xpack 的 GitHub Releases 下载 win32-x64 的 zip，解压到 C:\Users\你的用户名\.local\，把里面的 bin 目录也加进 PATH。

检查点
arm-none-eabi-gcc --version
网络慢的话

两个压缩包加起来约 600 MB，从 GitHub 下载在国内可能很慢或中断。用带断点续传的下载方式（curl -C - 或下载工具），不要用浏览器直接点。

2.5 先用合成信号把界面玩起来

编译动态库（只需一次），生成一段合成信号，打开调参界面：

python tools/build_native.py
python tools/make_testsig.py out/testsig.wav --seconds 4
python tools/tune_gui.py out/testsig.wav

会弹出一个窗口。点 ▶ 播放，边播边拖三个滑块，声音实时跟着变；右侧是两路频响曲线。勾选「A/B 旁通」再取消、来回几次——旁通时听到的是纯气导（别人听到的你），取消就是加了骨导之后的。

合成信号只能用来熟悉界面

它的"骨导"是用同一个激励源低通伪造的，跟真实颅骨传导没有物理对应。它能让你熟悉滑块的作用，不能用来判断音色像不像。后者只有真实录音能回答。

检查点

能播放、拖滑块声音有变化、频响曲线跟着动。到这里电脑侧就绪。

04

画板与打样

在立创 EDA 专业版里画两块小板，避开底部声孔、供电电压、MEMS 清洗这三个会让整批报废的坑。

4.1 两块板的网表

两块板电路几乎一样，唯一区别是 SELECT 接哪边——一块接地、一块接 3V3，这决定了它们各占时钟的哪个边沿。

GNDJ1.2　U1.GND　U1.SELECT　C1.2　C2.2
PDM_CLKJ1.3　U1.CLOCK
PDM_DATAJ1.4　U1.DATA

U1 的引脚编号从你拿到的 Knowles 手册填，上面只给了功能名。

4.2 三个会让整批报废的坑

坑一 · IM69D130 是底部声孔

PCB 要在器件正下方开一个 ⌀0.8 mm 的非金属化孔（麦克风自身声孔 ⌀0.6 mm，PCB 孔必须更大）。焊盘用阻焊定义（SMD）类型，焊环要完整以保证气密——漏气会毁掉低频。孔周围不要铺铜、不要开窗，免得锡膏流进去堵孔。骨导板不开任何孔。

坑二 · 必须用 3.3 V，不能用 1.8 V

两颗传感器都支持 1.62 V 起，很容易顺手选 1.8 V。但 IM69D130 的输出高电平最低只有 0.7 × VDD，1.8 V 时是 1.26 V，而 STM32 的 3.3 V 输入门限约 2.31 V——够不到。症状不是不工作，而是间歇性杂音，极难定位。本教程全程 3.3 V。

坑三 · MEMS 不能水洗、不能超声清洗

清洗液进入声腔会永久损坏振膜，而且损坏后表现为"能工作但音质差"，几乎无法判断。若板厂默认工序含清洗，下单时必须注明免洗。手工焊后也别用洗板水冲。

4.3 立创 EDA 操作要点

  • 建符号：器件 → 新建 → 符号。IM69D130 按上表填 5 个引脚；V2S200D 按 Knowles 手册填
  • 建封装：焊盘类型选「阻焊定义」；IM69D130 正下方放 ⌀0.8 mm 非金属化孔；丝印标出 Pin 1——底部端子器件贴反了看不出来
  • 布局：100 nF 放在 VDD 焊盘同层、2 mm 以内；CLK 与 DATA 走线尽量短、不换层
  • 骨导板加刚度：它是振动传感器，PCB 本身就是传导路径的一部分，留固定孔或用厚板，好压紧在皮肤上
  • 两块板拼在一个工程里打样，省钱
检查点

下单前对照：气导板有 ⌀0.8 mm 孔、骨导板无孔、两块板 SELECT 一个接地一个接 3V3、备注免洗。

05

开发板到货：先空板烧录

在接任何传感器之前，把固件烧进去、看灯确认它活着。这一步把"板子与固件"和"传感器"两类问题分开。

5.1 拉固件依赖并编译

HAL 库约 100 MB，从 ST 官方 GitHub 拉，不需要注册 ST 账号，只做一次：

bash firmware/vendor/fetch.sh
cd firmware/nucleo-h743
mingw32-make
检查点

最后打印体积，text 约 23 KB：

   text	   data	    bss	    dec	    hex	filename
  23276	     24	  16748	  40048	   9c70	build/capture.elf

链接时出现 _close/_read/_write is not implemented 与 RWX permissions 两类警告是正常的。

5.2 烧录：拖文件

  1. USB 线插开发板的 CN1 口（ST-Link 那一侧，不是 USB User 口）
  2. 电脑出现一个名为 NOD_H743ZI 的 U 盘
  3. 把 build\capture.bin 拖进去
  4. 板上 LD4 红绿交替闪几秒，然后 U 盘自动重新挂载——完成
Windows 会弹"复制失败"，但其实成功了

ST-Link 写完 Flash 会主动重新挂载磁盘，Windows 把这当成拔出。判断依据是板上的灯，不是弹窗。真失败时 U 盘里会出现 FAIL.TXT。另外只认 .bin，拖 .elf 或 .hex 不会报错但也不会烧。

5.3 看灯

绿灯 LD1红灯 LD3含义怎么办
每秒闪灭正常进入 5.4
每秒闪亮采集正常但串口丢块见附录 A
不闪常亮初始化失败八成是时钟；换了别的板子要把 HSE_BYPASS 改 HSE_ON
不闪灭程序没跑按黑色 RESET 键；确认拖的是 .bin

5.4 确认时钟在跑

固件会在 PC2 引脚输出 3.072 MHz 的时钟。在 Morpho 排针上找到丝印 PC2（对照 Nucleo-144 用户手册的引脚表）。

你有什么怎么测应该看到
逻辑分析仪接 PC2 与 GND，PulseView 采样 24 MHz3.072 MHz 方波，占空比 48–52%
只有万用表直流电压档测 PC2 对 GND≈1.65 V（3.3 V 的一半，因为占空比 50%）。读到 0 或 3.3 V 就是没输出

5.5 确认串口通

cd ..\..
python tools/capture.py --list

带 STLink 字样的那个串口就是。记下它的编号（下文用 COM5 代替）。然后：

python tools/capture.py COM5 --monitor
检查点

屏幕每秒刷新一行 CH0 RMS … CH1 RMS …，且没有 丢块 字样。现在还没接传感器，读数本身无意义，有读数在刷就说明整条链路通了。Ctrl+C 退出。

06

传感器板到货：贴装、接线、敲击测试

每次只引入一个新变量：先接一颗，再接第二颗，最后用敲击确定哪个声道是骨导。

6.1 贴装后先用万用表查

焊点看不见，电气检查是唯一手段。每块板查两样：3V3 与 GND 之间不短路（电阻档应为开路或很大）、四条网络各自从连接器到芯片焊盘导通。

6.2 接线

传感器板Nucleo 引脚备注
J.1 3V33V3板上直接取
J.2 GNDGND多接两根
J.3 PDM_CLKPC2串 100 Ω，电阻靠开发板一侧
J.4 PDM_DATAPC7串 100 Ω，电阻靠开发板一侧
台面调试先用 10–20 cm 短线

不要一上来就接一米屏蔽线。先把信号完整性这个变量排除掉；采集通了再换长线，那时出问题就知道是线的事。

6.3 先只接气导板（IM69D130）

它最容易验证——对着说话就该有反应。接好后：

python tools/capture.py COM5 --monitor
检查点

安静时某一个通道 DC 接近 0、RMS 很低；对着麦克风说话时该通道 RMS 明显上升。另一个通道此时应该近乎无信号或 DC 异常——因为那一边还没接。

这一步的读数怎么解读
读数含义
DC 接近 ±1数据线卡死或悬空：查 PC7 接线、传感器供电
RMS 为零不动传感器没输出：查 3V3、SELECT 是否悬空、100 nF 是否焊上
有信号但底噪大查 100 nF 是否紧靠 VDD、地线是否够粗
时好时坏、间歇杂音先确认供电是 3.3 V 不是 1.8 V

6.4 再接骨导板，做敲击测试

两块板并联接到同一组线上。再开 --monitor，用手指轻敲骨导传感器，看哪个通道的 RMS 跳——那个就是骨导。

不要靠推理判断 SELECT 高低对应左还是右，直接敲。方案约定左（CH0）= 骨导；如果实测相反，在处理时交换声道即可，不用改硬件。

检查点

两个通道内容不同；敲骨导只有一个通道跳；对着说话两个通道都有反应但骨导那路明显弱——弱是正常的，它需要补约 +20 dB，处理链里已经做了。

两个通道内容一模一样？

两块板的 SELECT 接成了同一电平。必须一块接地、一块接 3V3。

07

录素材

三个佩戴位置各录一组，每组四类内容，总共 12 段。这是回答"探头贴哪里"的直接依据。

用发带或医用胶带把骨导板压紧在皮肤上——松紧对信号影响极大，这本身也是要试的东西。气导麦放嘴角侧面 2–3 cm、略偏轴，不要正对嘴，避开气流。

位置内容目的
乳突（耳后骨突）
下颌骨
喉部		正常说话基准
轻声说话信噪比够不够
唱一段动态余量、会不会削波
"四十四只石狮子"齿音，看高频与清晰度

每段 15–30 秒。文件名带上位置，方便后面对比：

python tools/capture.py COM5 out/乳突_说话.wav -d 20
python tools/capture.py COM5 out/乳突_唱歌.wav -d 30
python tools/capture.py COM5 out/下颌_说话.wav -d 20
…
检查点

每次录完会打印两声道峰值。骨导那路在 −40 到 −20 dBFS 之间、气导在 −20 到 −6 dBFS 之间都算正常。气导超过 −1 dBFS 说明离嘴太近或唱太响，削波了。

08

调参与判定

用真实录音找到"像"的参数，填完记录表，拿到三个答案。

8.1 打开界面

python tools/tune_gui.py out/乳突_说话.wav

8.2 最容易毁掉判断的坑

响的那个总是听起来更好

混合比从 0 推到 1，输出峰值会涨 3–4 dB（骨导路有 +20 dB 归一化增益）。不补偿的话，你会误以为"骨导多一点更好听"，其实只是听到了更响。每次改完混合比，先用输出电平滑块把左下角的峰值读数拉回原值，再判断音色。A/B 旁通同理。

8.3 调参顺序

  1. 先关限幅、设好电平——限幅会压掉动态，干扰判断。让峰值落在 −6 到 −3 dBFS
  2. 定混合比——从 0.5 开始，先大幅左右扫出"明显太薄"和"明显太闷"两个边界，再二分逼近。每次改完补电平
  3. 调音色——混合比定了再细修。这个滑块一动同时改三个参数，左下角读数能看到
  4. 回头微调混合比——音色变了最佳混合比会漂，来回两三轮收敛
  5. 最后打开限幅，确认没有明显压缩感

8.4 判据：不是"好听"，是"像"

融合判据

戴封闭式耳机，边说话边听处理后的信号。参数对了，处理声会和你自然的自听"融"在一起，感觉只是自己变响了；不对，你会听到明显的"两个人在说话"的分离感或梳状染色。分离感消失的位置就是答案。

这比"回忆刚才的声音"可靠得多——人对音色的听觉记忆只有几秒，且极不稳定。

界面里还有一个「延迟模式」开关：natural（423 µs，复现你自然的听觉时序）和 coherent（73 µs，两路严格对齐、更"干净"）。哪个更像没有理论答案，用耳朵定。

8.6 怎么解读结果

能"融"

概念成立。把滑块位置记下来，它们会成为固件的默认参数。接下来进入第二阶段：腰包主板（DAC、麦克风电平输出、幻象电源耐受、旋钮、电池）。

怎么调都融不起来

先别下结论。换另一个佩戴位置重试；用 --monitor 确认骨导信号本身干净（DC≈0、说话时 RMS 有明显变化）。三个位置都试过、信号质量确认没问题，才谈得上"概念不成立"。

它经过四轮审查、修掉了七个"编译通过但上机不工作"的缺陷，并验证了 DMA 缓冲位置与时钟推导。但时钟树能否真出 3.072 MHz、DFSDM 两通道配对、串口能否跑到 4 Mbaud，只有上电才知道。第 5 部分"先空板烧录看灯"正是为此设计的——那一步不过，后面接什么都白搭。
